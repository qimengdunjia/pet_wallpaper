# 车机宠物交互壁纸 PRD

| 项目 | 说明 |
| --- | --- |
| 版本 | V1.0 草案，2026-11-26 同步飞书 |

## 01 项目背景

### 1.1 Demo 目标

- 在一台演示车机上稳定展示猫咪和狗狗两种宠物壁纸，支持首次录入、增加宠物、切换和恢复上次使用的壁纸。
- 用户等待生成时，播放猫狗入场和追逐动画。资源就绪后进入目标壁纸。有历史壁纸时，生成失败回到上次成功的画面。
- 壁纸画布能根据单次点击的横向位置播放对应动作。每段从同一中性待机姿态开始并回到该姿态，避免跳帧和角色漂移。

### 1.2 本期范围（P0）

| 模块 | 能力 |
| --- | --- |
| 猫狗双模式 | 支持猫咪、狗狗两类壁纸和独立宠物档案，记录当前使用者上次成功显示的宠物 |
| 生成与过场 | 首次录入或新增宠物时，上传照片后先生成宠物静态图供用户确认，可选背景颜色和配件。确认后生成壁纸及动作资源，等待时按第 4.4 节播放过场。选择已就绪的宠物时直接加载目标壁纸 |
| 点击交互 | 本期确认采用左、中、右三热区，猫咪和狗狗各三段动作，坐标见第 05 章 |
| 运行状态 | 停车时开放完整互动，行驶、生成和动作播放中的操作按第 08 章限制 |
| 视觉参考 | 以近景萌宠、背景景深和前景承托表现空间感 |

## 02 体验流程与页面状态

### 2.1 主要用户路径

- **首次创建。** 进入壁纸 → 选择「猫咪」「狗狗」或「猫狗都有」→ 上传对应照片 → 查看生成的静态图，可选背景和配件 → 确认静态图并提交生成 → 播放加载过场 → 首套资源就绪后进入壁纸并响应点击。
- **再次进入。** 读取当前使用者及上次成功显示的宠物。已有可用壁纸时复用已保存资源，未录入时进入首次创建流程。
- **切换已有宠物。** 从壁纸打开宠物选择，按猫咪或狗狗分类选择已就绪的目标。确认后直接显示目标壁纸，成功后将目标记录为当前宠物。
- **新增宠物。** 从宠物选择入口进入添加流程，选择类型、上传照片并确认静态图，再提交生成。资源完整后进入或选择新壁纸。

### 2.2 页面状态与反馈

| 状态 | 页面表现及退出条件 |
| --- | --- |
| 首次录入 | 展示宠物类型和相应上传入口。原型中选择类型后启用「下一步」，照片可替换或重新上传 |
| 静态图确认 | 展示上传照片生成的宠物静态图，提供背景颜色和配件选项。用户确认后进入壁纸及动作资源生成 |
| 生成等待 | 播放 3 秒先导，再播放 7 秒追逐段。若仍在生成，只循环追逐段。期间暂停热区响应，系统控件保持可用 |
| 壁纸待机 | 目标资源就绪后显示目标宠物壁纸，按第 08 章开放画布有效区点击 |
| 动作播放 | 完整播放当前热区的预生成视频，随后回到中性待机姿态。播放期间暂停宠物切换及热区点击，必要系统提示可中断播放 |
| 选择或切换 | 选择面板显示宠物分类、缩略图、当前选中态和生成状态。目标切换成功后更新当前壁纸，失败时返回原壁纸 |
| 退出与恢复 | 原型中退出壁纸返回应用首页，首页显示上次使用的宠物。再次进入壁纸时加载已保存资源 |

## 03 页面结构与视觉表现

### 3.1 页面层级

| 层级 | 内容和触摸规则 |
| --- | --- |
| 系统控件层 | 导航、返回、状态栏、必要的驾驶提醒和安全弹层具有最高优先级，过场期间仍可使用 |
| 模式控件层 | 壁纸上提供易识别的「宠物选择」入口，选择面板承接猫狗分类、宠物切换和「添加宠物」 |
| 壁纸显示层 | 显示当前猫咪或狗狗的主视觉。画布有效区域内的点击按第 05 章映射到动作 |

### 3.2 视觉方向

- 猫狗模式各有自己的背景和稳定的宠物展示位置。采用近景构图，将头部、胸前和前爪作为视觉焦点。
- 通过前景承托面、背景景深、合理遮挡、毛发与环境光的层次表现空间感。背景简洁，界面只保留操作所需元素。
- 同一宠物的待机与互动用同一场景和镜头机位。理想 OTA 8.2 在原稿中用作宠物近景及场景氛围的参考，车机侧采用原创构图与交互。
- 画面的实际立体呈现以目标屏幕、视差方案与视频素材能力为准，硬件能力待联评。

### 3.3 入口、点击优先级与驾驶限制

- 宠物选择入口独立于壁纸画布。宠物选择面板、导航、功能按钮与系统弹层独占其覆盖区域的点击。面板关闭后恢复壁纸热区响应。
- 添加或切换使用者、上传照片和编辑宠物资料仅允许驾驶员在安全停车状态下操作。

## 04 首次录入与多宠

### 4.1 首次录入

| 节点 | 车机规则 |
| --- | --- |
| 进入 | 原稿规定无宠物时直接显示类型选择，姓名填写和账号创建均可跳过。原型另有欢迎页和「创建我的宠物档案」入口 |
| 选择与上传 | 提供「猫咪」「狗狗」「猫狗都有」。每只宠物上传一张清晰正面照，选择两种时分别提供猫和狗的上传入口 |
| 静态图确认 | 上传后生成对应宠物的静态图，按第 4.3 节提供背景颜色和配件选项，由用户确认画面 |
| 提交 | 确认后点击「生成壁纸」，创建宠物档案并生成壁纸资源。每只宠物的各方向动作使用该宠物确认的同一张静态图作为参考 |
| 等待 | 按第 4.4 节播放先导和追逐等待段 |
| 完成 | 壁纸与各方向互动视频就绪后，可进入该宠物壁纸。选择「猫狗都有」时优先进入首套就绪壁纸，另一只在列表显示「生成中」，就绪后可选 |

### 4.2 切换与新增

- **选择已有宠物。** 同种和跨种采用同一规则。确认选择时，目标已具备待机图和全部热区视频，则加载已有资源，直接进入目标宠物的待机画面。切换与互动按第 08 章限制。
- **添加宠物。** 选择猫或狗，上传照片并按第 4.3 节确认静态图。提交后分配独立 Pet ID，各自保存壁纸和动作资源。需要用户等待时按第 4.4 节播放过场。资源齐套前列表显示「生成中」，就绪后开放选择。切换或新增失败时保留当前成功显示的壁纸。
- **宠物资料。** 原型在上传与编辑页面展示昵称、性别、品种，并在切换确认页提供「编辑信息」入口。资料可保存，必填规则待确认。

### 4.3 自定义背景和装饰

上传宠物照片后，先生成并展示宠物静态图供用户确认。用户可在确认阶段选择背景颜色和宠物配件。

| 项目 | 可选项 |
| --- | --- |
| 背景颜色 | 米白色、浅粉色、浅蓝色、浅紫色 |
| 宠物配件 | 领结、口水巾、眼镜、圣诞帽 |

同一宠物的待机壁纸和各热区动作以确认后的画面为参考，保持背景和配件一致。款式和颜色见[飞书第 4.3 节参考图](https://my-ichery.feishu.cn/docx/H81WdIo3voi2eUx1KG2chVotnEf#Z3vXd678No3MyOx32Drcdp2nnvf)。

### 4.4 生成等待与过场

以下流程适用于用户进入视频生成等待的场景。

1. **先导，3 秒。** 猫狗先后跑入画面中央并持续奔跑。每次进入生成等待时播放一次。
2. **等待段，7 秒。** 首轮过场共 10 秒。若首轮结束时目标资源仍未准备好，继续循环 7 秒追逐段，先导只播放一次。
3. **资源就绪。** 加载目标宠物壁纸，成功显示后记录为当前壁纸，按第 08 章开放互动。循环期间的具体切出点待确认。

过场采用固定镜头和统一背景。视觉中心随领先宠物平滑转移。等待段首尾保持猫前狗后的构图和奔跑姿态，先导末尾接入相同姿态。

## 05 屏幕热区与点击映射

壁纸画布采用左、中、右三个热区。单击按画布宽度归一化计算横坐标 `x`，点击有效区后按宠物种类和方向选择第 07 章对应动作。

| 画面方向 | 横向坐标 | 参考中心 | 原表编号 |
| --- | --- | --- | --- |
| 左 | 0% ≤ x < 34% | 17% | Z2 |
| 中 | 34% ≤ x < 66% | 50% | Z3 |
| 右 | 66% ≤ x ≤ 100% | 83% | Z5 |

本期 Demo 按本表实现和验收，猫咪和狗狗各需左、中、右三段互动素材。飞书第 5.1 节插图中的分区比例和编号仅作布局参考。

## 06 伸爪与探头动作

- **待机构图。** 宠物正面趴卧，正脸居中，身体约占画面六成，并为前爪和头部预留动作空间。未自定义背景时采用模板默认场景。同一宠物的待机与互动素材共享镜头、中性姿态及第 4.3 节确认的背景和配件。
- **动画结构。** 中性待机 → 抬爪或抬头前伸 → 在目标位置轻触或短暂停留 → 收爪或收头 → 回到同一待机姿态。首尾帧与待机图衔接，角色外观和位置稳定。
- **播放方式。** AI 生成阶段准备固定动作视频，车机收到点击后仅选择并播放对应素材。猫用肉垫伸爪轻触，狗用鼻尖探头轻触。

## 07 动画资产

下表所有视频的目标输出为 **1920 × 1080、16:9、24 fps**。猫狗各有三段 4 秒互动视频，另有加载过场和待机素材。过场使用统一的半写实环境，蓝天白云约占画面三分之二，绿地约占三分之一。

| 类别 | 素材 | 时长 | 动作与衔接 |
| --- | --- | --- | --- |
| 加载过场 | 入场先导 | 3 秒 | 猫狗先后跑入画面中央，保持奔跑。尾帧接等待段首帧，每次加载只播放一次 |
| 加载过场 | 等待循环 | 7 秒 | 猫前狗后开始，狗超到前方，猫再追到前方，回到与首帧一致的位置和姿态 |
| 猫 | 中性待机 | 4 秒 | 正面居中趴卧，目视前方，首尾帧一致 |
| 狗 | 中性待机 | 4 秒 | 正面居中趴卧，目视前方，首尾帧一致 |
| 猫 | 待机壁纸动效 | 4 秒 | 正面趴卧，抬起自身右前爪舔舐爪部毛发 |
| 狗 | 待机壁纸动效 | 4 秒 | 正面趴卧，朝前嗅闻两次，随后咧嘴微微吐舌 |
| 猫 | 左热区 | 4 秒 | 用自身右前爪伸向画面左区，以肉垫轻触后收回原爪 |
| 猫 | 中热区 | 4 秒 | 用自身左前爪伸向镜头正前方，以肉垫轻触后收回 |
| 猫 | 右热区 | 4 秒 | 用自身左前爪伸向画面右区，以肉垫轻触后收回原爪 |
| 狗 | 左热区 | 4 秒 | 快速抬头、微吐舌、摇尾，合嘴后向画面左区探头，以鼻尖微微向上触碰后回到趴卧 |
| 狗 | 中热区 | 4 秒 | 快速抬头、微吐舌、摇尾，沿镜头轴向前探头，以鼻尖微微向上触碰后回到趴卧 |
| 狗 | 右热区 | 4 秒 | 快速抬头、微吐舌、摇尾，向画面右区探头，以鼻尖微微向上触碰后回到趴卧 |

素材方向按观众看到的画面验收。猫收回实际伸出的前爪，狗以鼻尖触碰对应区域。早期资产截图中的「猫切狗」「狗切猫」可参见[算法区加载动画文档](../algorithm-lab/docs/ComfyUI_宠物加载动画.md)。

## 08 运行状态与驾驶安全

| 运行状态 | 宠物切换 | 画布互动 | 壁纸展示与系统优先级 |
| --- | --- | --- | --- |
| 演示停车 | 允许 | 允许 | 展示完整壁纸和过场，系统提醒优先 |
| 车辆行驶中 | 限制驾驶员发起切换 | 禁用驾驶员互动 | 保留动态壁纸和必要显示，导航与行车信息优先 |
| 生成进行中 | 禁止重复发起 | 禁用 | 播放过场或等待段，系统控件继续响应，必要信息可覆盖壁纸 |
| 播放互动动画中 | 暂时锁定切换入口 | 暂停接收新点击 | 单段动作完整播放，必要系统提示可中断 |

## 验收标准

### 车机交互

| 场景 | 验收结果 |
| --- | --- |
| 首次录入单宠或猫狗 | 单宠可独立生成。猫狗均提交时可先展示首套就绪壁纸，另一只就绪后变为可选 |
| 静态图确认与自定义 | 首次录入和新增宠物时，上传照片后均可查看并确认生成的静态图。逐项验证四种背景颜色和四种配件可选。确认后生成的壁纸和动作素材采用对应宠物所选的背景与配件 |
| 生成等待与切出 | 首轮依次播放 3 秒先导和 7 秒追逐段。模拟生成超过 10 秒，验证仅重复 7 秒段。资源就绪后进入目标壁纸，猫和狗分别验证 |
| 过场触摸优先级 | 过场中壁纸热区暂停响应，系统导航、返回与驾驶提醒可用。进入目标壁纸后恢复热区响应 |
| 恢复壁纸 | 再次进入可恢复当前使用者上次成功显示的壁纸 |
| 切换已就绪的宠物 | 分别验证同种和跨种切换。确认后的下一画面为目标宠物的待机图，热区点击可触发对应动作。加载失败时保留原壁纸 |
| 热区映射 | 猫狗各验证左、中、右三段。34% 归中区，66% 归右区。功能按钮、选择面板和系统弹层各自处理覆盖区内的点击 |
| 运行状态与驾驶限制 | 停车时验证完整交互。行驶时验证热区禁用、切换受限，第 3.3 节的停车操作被拦截，导航与行车信息优先。生成中验证重复发起被拦截。动作播放时验证连点被忽略、切换入口锁定、必要系统提示可以中断 |

### 网页素材

| 环节 | 验收结果 |
| --- | --- |
| 待机素材 | 猫狗各用一张清晰正面照，检查身份特征、正面趴卧、正脸居中、背景与完整前爪。检查中性待机首尾帧及两种待机动效 |
| 交互视频 | 每只宠物用同一张待机图生成左、中、右三段。动作到达相应参考区，镜头和宠物外观稳定，首尾回到同一待机姿态 |
| 加载过场 | 检查 3 秒先导到 7 秒等待段，以及等待段首尾循环的构图、角色位置和奔跑相位 |
| 文件规格 | 实测分辨率、宽高比、平均帧率和时长，目视复核动作及衔接观感 |
