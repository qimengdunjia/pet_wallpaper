# 车机宠物交互壁纸 PRD

| 项目 | 说明 |
| --- | --- |
| 版本 | V1.0 草案，整理于 2026-11-20 |
| 业务范围 | AI 宠物动态壁纸 Demo |
| 演示设备 | 暂按一台 15.6 英寸横屏车机，视频素材采用 16:9 |
| 评审状态 | 基础交互已定义，视觉、性能及车机限制待联评 |

## 01 项目背景

### 1.1 Demo 目标

- 在一台演示车机上稳定展示猫咪和狗狗两种宠物壁纸，支持首次录入、增加宠物、切换和恢复上次使用的壁纸。
- 用户等待视频生成时，以追逐动画提示壁纸正在准备。资源就绪后播放目标方向的切换动画，再进入壁纸。有历史壁纸时，生成失败回到上次成功的画面。
- 壁纸画布能根据单次点击的横向位置播放对应动作。每段从同一中性待机姿态开始并回到该姿态，避免跳帧和角色漂移。

### 1.2 本期范围（P0）

| 模块 | 能力 |
| --- | --- |
| 猫狗双模式 | 支持猫咪、狗狗两类壁纸和独立宠物档案，记录当前使用者上次成功显示的宠物 |
| 生成与过场 | 首次录入或新增宠物时生成壁纸及动作资源。需要等待视频时循环播放 7 秒追逐段，就绪后接 3 秒切换动画。选择已就绪的宠物时直接加载目标壁纸 |
| 点击交互 | 已确认采用左、中、右三热区，猫咪和狗狗各三段动作，点击时按当前宠物和热区播放对应素材 |
| 视觉参考 | 以近景萌宠、背景景深和前景承托表现空间感 |

## 02 体验流程与页面状态

### 2.1 主要用户路径

- **首次创建。** 进入壁纸 → 选择「猫咪」「狗狗」或「猫狗都有」→ 上传对应照片 → 提交生成 → 循环播放追逐动画 → 首套资源就绪后接入对应切换动画 → 进入壁纸并响应点击。
- **再次进入。** 读取当前使用者及上次成功显示的宠物。已有可用壁纸时复用已保存资源，未录入时进入首次创建流程。
- **切换已有宠物。** 从壁纸打开宠物选择，按猫咪或狗狗分类选择已就绪的目标。确认后直接显示目标壁纸，成功后将目标记录为当前宠物。
- **新增宠物。** 从宠物选择入口进入添加流程，选择类型、上传照片并提交，资源完整后进入或选择新壁纸。

### 2.2 页面状态与反馈

| 状态 | 页面表现及退出条件 |
| --- | --- |
| 首次录入 | 展示宠物类型和相应上传入口。原型中选择类型后启用「下一步」，照片可替换或重新上传 |
| 生成等待 | 循环播放 7 秒追逐段，暂停壁纸热区响应，车机系统控件保持可用。目标资源就绪后进入切换过场 |
| 生成完成过场 | 按目标物种播放一次 3 秒切换动画。播完进入目标壁纸并开放热区响应 |
| 壁纸待机 | 显示当前宠物的中性待机图，响应画布有效区单击 |
| 动作播放 | 播放对应热区的预生成视频，结束后回到同一待机画面 |
| 选择或切换 | 选择面板显示宠物分类、缩略图、当前选中态和生成状态。目标切换成功后更新当前壁纸，失败时返回原壁纸 |
| 退出与恢复 | 原型中退出壁纸返回应用首页，首页显示上次使用的宠物。再次进入壁纸时加载已保存资源 |

## 03 页面结构与视觉表现

### 3.1 页面层级

| 层级 | 内容和触摸规则 |
| --- | --- |
| 系统控件层 | 导航、返回、状态栏、必要的驾驶提醒和安全弹层具有最高优先级，过场期间仍可使用 |
| 模式控件层 | 壁纸上提供易识别的「宠物选择」入口，选择面板承接猫狗分类、宠物切换和「添加宠物」 |
| 壁纸显示层 | 显示当前猫咪或狗狗的主视觉。画布有效区域内的点击按第 05 章映射到动作 |

### 3.2 视觉方向

- 猫狗模式各有自己的背景和稳定的宠物展示位置。采用近景构图，将头部、胸前和前爪作为视觉焦点。
- 通过前景承托面、背景景深、合理遮挡、毛发与环境光的层次表现空间感。背景简洁，界面只保留操作所需元素。
- 同一宠物的待机与互动用同一场景和镜头机位。理想 OTA 8.2 在原稿中用作宠物近景及场景氛围的参考，车机侧采用原创构图与交互。
- 画面的实际立体呈现以目标屏幕、视差方案与视频素材能力为准，硬件能力待联评。

### 3.3 入口、点击优先级与驾驶限制

- 宠物选择入口独立于壁纸画布。宠物选择面板、导航、功能按钮与系统弹层独占其覆盖区域的点击。面板关闭后恢复壁纸热区响应。
- 添加或切换使用者、上传照片和编辑宠物资料仅允许驾驶员在安全停车状态下操作。

## 04 首次录入与多宠

### 4.1 首次录入

| 节点 | 车机规则 |
| --- | --- |
| 进入 | 原稿规定无宠物时直接显示类型选择，姓名填写和账号创建均可跳过。原型另有欢迎页和「创建我的宠物档案」入口 |
| 选择与上传 | 提供「猫咪」「狗狗」「猫狗都有」。每只宠物上传一张清晰正面照，选择两种时分别提供猫和狗的上传入口 |
| 提交 | 点击「生成壁纸」创建宠物档案并发起生成请求。每只宠物先生成一张待机图，再使用同一张待机图生成各方向动作 |
| 等待 | 用户需要等待视频生成时，按第 4.3 节循环播放 7 秒猫狗追逐段 |
| 完成 | 待机图和各方向视频均已生成时，按第 4.3 节结束生成等待并进入该宠物壁纸。选择「猫狗都有」时优先进入首套就绪壁纸，另一只在列表显示「生成中」，就绪后可选 |

### 4.2 切换与新增

- **选择已有宠物。** 同种和跨种采用同一规则。确认选择时，目标已具备待机图和全部热区视频，则加载已有资源，直接进入目标宠物的待机画面并启用热区互动。
- **添加宠物。** 选择猫或狗并上传照片。提交后分配独立 Pet ID，各自保存壁纸和动作资源。需要用户等待视频生成时按第 4.3 节播放，完整资源生成后开放选择。切换或新增失败时保留当前成功显示的壁纸。
- **宠物资料。** 原型在上传与编辑页面展示昵称、性别、品种，并在切换确认页提供「编辑信息」入口。资料可保存，必填规则待确认。

### 4.3 生成等待与切换过场

以下流程适用于用户进入视频生成等待的场景。

1. **等待视频生成。** 直接循环播放 7 秒猫狗追逐动画，直到目标宠物的待机图和互动视频全部就绪。
2. **生成完成。** 从等待循环接入一段 3 秒切换动画。目标是狗狗时播放「猫切狗」，目标是猫咪时播放「狗切猫」。首次录入也按将要展示的宠物选择片段。
3. **切换动画结束。** 进入目标宠物的壁纸待机画面，启用热区互动。

过场采用固定镜头和统一背景。两只宠物通过相对位移表现追逐，画面视觉中心随领先宠物平滑转移。等待段首尾保持猫前狗后的奔跑姿态，接入两个方向的切换片段时都需保持构图与动作连贯。

## 05 屏幕热区与点击映射

壁纸画布采用左、中、右三个热区。单击按画布宽度归一化计算横坐标 `x`，点击有效区后按宠物种类和方向选择第 07 章对应动作。

| 画面方向 | 横向坐标 | 参考中心 | 原表编号 |
| --- | --- | --- | --- |
| 左 | 0% ≤ x < 34% | 17% | Z2 |
| 中 | 34% ≤ x < 66% | 50% | Z3 |
| 右 | 66% ≤ x ≤ 100% | 83% | Z5 |

原稿第 5.1 节的示意图标为 Z2、Z3、Z4，范围依次为 20–40%、40–60%、60–80%，仅作布局参考。车机点击映射以本表为准。

## 06 伸爪与探头动作

- **待机图。** 宠物正面趴卧，正脸居中，身体约占画面六成，并为前爪和头部预留动作空间。交互背景由用户定义，同一宠物共享背景、镜头与待机图。
- **动画结构。** 中性待机 → 抬爪或抬头前伸 → 在目标位置轻触或短暂停留 → 收爪或收头 → 回到同一待机姿态。首尾帧与待机图衔接，角色外观和位置稳定。
- **播放方式。** AI 生成阶段准备固定动作视频，车机收到点击后仅选择并播放对应素材。猫用肉垫伸爪轻触，狗用鼻尖探头轻触。

## 07 动画资产

下表所有视频的目标输出为 **1920 × 1080、16:9、24 fps**。当前网页素材验收包含**六段交互视频与三个过场片段**。过场使用统一的半写实环境，蓝天白云约占画面三分之二，绿地约占三分之一。

| 类别 | 素材 | 时长 | 动作与衔接 |
| --- | --- | --- | --- |
| 生成等待 | 等待循环 | 7 秒 | 猫前狗后开始，狗超到前方，猫再追到前方。回到与起始一致的位置和姿态，保持循环连续 |
| 生成完成过场 | 猫切狗 | 3 秒 | 猫先居中奔跑，狗从画面左侧追上并占据中央，猫相对向左退出。接狗狗壁纸 |
| 生成完成过场 | 狗切猫 | 3 秒 | 狗先居中奔跑，猫从画面左侧追上并占据中央，狗相对向左退出。接猫咪壁纸 |
| 猫 | 左热区 | 4 秒 | 用自身右前爪伸向画面左区，以肉垫轻触后收回原爪 |
| 猫 | 中热区 | 4 秒 | 用自身左前爪伸向镜头正前方，以肉垫轻触后收回 |
| 猫 | 右热区 | 4 秒 | 用自身左前爪伸向画面右区，以肉垫轻触后收回原爪 |
| 狗 | 左热区 | 4 秒 | 快速抬头、微吐舌、摇尾，合嘴后向画面左区探头，以鼻尖微微向上触碰后回到趴卧 |
| 狗 | 中热区 | 4 秒 | 快速抬头、微吐舌、摇尾，沿镜头轴向前探头，以鼻尖微微向上触碰后回到趴卧 |
| 狗 | 右热区 | 4 秒 | 快速抬头、微吐舌、摇尾，向画面右区探头，以鼻尖微微向上触碰后回到趴卧 |

原资产表在跨种切换角色、猫侧向收爪及狗侧向参考图上存在方向冲突。当前按表中口径验收，跨种素材以目标宠物居中收尾，猫收回实际伸出的前爪，狗以观众看到的方向触碰对应区域。

## 验收标准

### 车机交互

| 场景 | 验收结果 |
| --- | --- |
| 首次录入单宠或猫狗 | 单宠可独立生成。猫狗均提交时可先展示首套就绪壁纸，另一只就绪后变为可选 |
| 生成等待与切出 | 模拟视频生成跨过多个 7 秒周期。目标资源就绪时，接入正确的 3 秒切换动画，播完进入目标壁纸。猫和狗分别验证 |
| 过场触摸优先级 | 过场中壁纸热区暂停响应，系统导航、返回与驾驶提醒可用。进入目标壁纸后恢复热区响应 |
| 恢复壁纸 | 再次进入可恢复当前使用者上次成功显示的壁纸 |
| 切换已就绪的宠物 | 分别验证同种和跨种切换。确认后的下一画面为目标宠物的待机图，热区点击可触发对应动作。加载失败时保留原壁纸 |
| 热区映射 | 猫狗各验证左、中、右三段。34% 归中区，66% 归右区。功能按钮、选择面板和系统弹层各自处理覆盖区内的点击 |
| 驾驶限制 | 安全停车时驾驶员可执行第 3.3 节列明的操作，其他车辆状态下入口按车机安全策略拦截 |

### 网页素材

| 环节 | 验收结果 |
| --- | --- |
| 待机图 | 猫狗各用一张清晰正面照，检查身份特征、正面趴卧、正脸居中、背景与完整前爪 |
| 交互视频 | 每只宠物用同一张待机图生成左、中、右三段。动作到达相应参考区，镜头和宠物外观稳定，首尾回到同一待机姿态 |
| 等待与切换过场 | 检查 7 秒段首尾循环，再分别接入猫切狗和狗切猫，验证构图、角色位置及奔跑相位的连续性。切换段以目标物种居中收尾 |
| 文件规格 | 实测分辨率、宽高比、平均帧率和时长，目视复核动作及衔接观感 |

## 待确认事项

| 事项 | 当前依据与待定内容 |
| --- | --- |
| 首次入口与资料 | 原文从类型选择开始，原型先显示欢迎页并展示宠物资料字段。首屏路径及资料字段必填规则待定 |
| 播放与恢复细节 | 首次生成失败且无历史壁纸时的反馈及重试、动作播放期间的连点处理待定 |
| 车机联评 | 视觉定稿、目标屏幕的立体呈现方式、性能指标与车辆安全状态判定待联评 |
